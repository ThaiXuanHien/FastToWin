This preserves the existing single authoritative engine process model; concurrent engine processes sharing one active-room table are outside scope. The source mutex retry count is bounded, but JDBC waits retain existing repository/pool behavior; no new database pool or unrelated engine refactor. Global persistence serialization means a slow active-room write can delay other persistence operations while engine mutex is free. After capture, participant disconnect is treated as an already admitted match; before capture it invalidates and refunds. An uncertain write stays fenced until durable retry/maintenance abort. A process crash before durable snapshot refunds startup reservations; a durable active/pending/completed record finalizes them. If refund/finalization storage also fails, RESERVED receipts remain for startup reconciliation; no potentially started record is guessed refundable. Custom quota implementations now have an explicit compilation migration cost instead of unsafe silent fallback.
