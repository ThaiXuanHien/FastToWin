## Resulting behavior

Owner/Operator prepare bilingual drafts and previews; only Owner publishes/cancels; Support reads history and reports. Publication validates the current session, role, Origin, CSRF, positive version, request identity, preview token and registered audience before replay. It freezes unique registered recipients. Missing/guest/deleted selected IDs block publication; accounts registered afterwards are excluded. Published copy is immutable; corrections are new announcements referencing an old ID.

In-app is always enabled; home banner and push are separate explicit options, push default off. Scheduled notifications materialize durably with a per-recipient checkpoint. Offline catch-up after the exclusive end stores expired history without a late banner/push. Cancellation stops pending work and preserves existing cancelled history. Read, inbox dismissal and banner hiding are separate durable facts across devices. Notifications never award assets, cancel gifts, change event factors or maintenance policy, or automatically install updates.

The player inbox combines paginated authenticated announcement history with legacy social rows, deduplicates IDs and preserves loaded pages during background refresh. Plain authored Vietnamese/English copy, category, lifecycle state and UTC bounds appear in a scrollable detail. A fresh detail clock comes from the accepted read-only banners envelope before waiting for a read mutation. Identity/view/request fences reject obsolete responses; a server-anchored clock removes active banners at the exclusive end. No automatic modal, focus theft, match interruption or reward action is added. Internal actions admit event, mailbox, update information and previous-announcement targets only. Native update uses the existing bridge and explicitly reports unsupported installation capability where applicable.

Separate admin/event push consent defaults false and preserves the four legacy preference categories. Uncertain retries retain the same intent/version; conflicts require fresh authority. A committed push attempt is never automatically resent after UNKNOWN. Provider I/O has a 20-second deadline, stale attempts recover to UNKNOWN with audit after 120 seconds. V59 adds indexed internal pending keys with transactional enqueue/dequeue/cancel and a bounded candidate page; each candidate still revalidates current authority immediately before claim. Stale candidates can underfill a batch until the next poll. V58 and other applied migrations are unchanged.

The white Material admin console uses native modal forms, 48px labelled utility icons, readable publication/cancellation actions and independent exact BigInt counters. It distinguishes frozen/eligible/pending/stored/read and provider accepted/failed/unknown facts without adding overlapping counters together or calling acceptance a read.
